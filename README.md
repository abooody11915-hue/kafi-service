# KAFI Service

منصة خدمات مستقلة مستخرجة من نظام الصيانة المجرب في كافي ٢، مع الاحتفاظ بأفضل الواجهات والتدفقات والمنطق وتحسين حدود الأمان ومصادر الحقيقة. لا تعتمد على Lovable أو قاعدة كافي ٢ في التشغيل، ولا تنسخ أي مستخدم أو مزود أو طلب قديم.

## ما تم استخراجه وتحسينه

- كتالوج كافي ٢ الكامل: 26 خدمة ضمن 6 عائلات، مع صور الخدمات وسياسات الضمان/الجودة/إعادة التوصيل المناسبة لكل نوع.
- رحلة العميل: اختيار الخدمة، وصف المشكلة، العنوان والموعد، الدخول عند التأكيد، المرفقات الخاصة، مقارنة العروض، التنفيذ، الفاتورة، الدفع والضمان.
- رحلة المزود: التسجيل، اختيار الخدمات، توثيق الهوية/السجل/الآيبان، مراجعة الامتثال، تسعير الفرص، حالات التنفيذ والتسويات.
- مركز الأونر: مراقبة الطلبات، توثيق المزودين، واعتماد التسويات بصلاحيات منفصلة.
- أوامر RPC ذرّية مع تحقق من الحالة المتوقعة، Idempotency وسجل أحداث بدل تعديل الحالة مباشرة من الواجهة.

## مبادئ غير قابلة للتفاوض

- Supabase Auth هو مصدر الهوية، وجداول العضوية هي مصدر الصلاحيات.
- RLS حاجز البيانات النهائي، ولا تعتمد الصلاحيات الحساسة على واجهة المستخدم.
- انتقالات الطلب الحساسة تتم عبر Commands/RPC مع سجل أحداث وIdempotency.
- الفاتورة والمعاملة والتسوية هي مصادر الحقيقة المالية، ولا تحسب الواجهة مبالغ نهائية مستقلة عن قاعدة البيانات.
- جميع المستندات والوسائط خاصة وتُعرض بروابط موقعة قصيرة العمر.
- بيانات التطوير اصطناعية فقط.

## تشغيل محلي

```bash
npm install
cp .env.example .env.local
npm run test
npm run build
```

لن يبدأ التطبيق إذا لم تُضبط متغيرات Supabase، لتجنب تشغيل نسخة متصلة ببيئة غير مقصودة.

## الحالة الحالية

العمود الرأسي الأساسي مكتمل من إنشاء الطلب حتى التسوية والضمان، مع Storage خاص وRealtime وRLS. لا تزال بوابة دفع إلكترونية، إشعارات Push، وسياسات تشغيل تلقائية مجدولة مراحل مستقلة قبل الإطلاق العام.
